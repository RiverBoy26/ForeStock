# Уточнение архитектуры после чекпоинта

Для команды разработки и при необходимости пояснения организаторам.

На чекпоинте обсуждалась концепция прогноза с пятью функциональными блоками (индивидуальный прогноз товара, независимая модель, прогноз агрегированного спроса, выбор эксперта, коррекция количества). Такая схема присутствовала в исследовательской работе, но устное описание не разграничило её и архитектуру конкретной конкурсной отправки.

После анализа результатов лидерборда команда закрепила `прогноз_5` / v8.1 как **сигнатурную базовую версию**, поскольку она показала лучший результат среди первых пяти отправок. Воспроизведение из исходных артефактов подтвердило фактическую конфигурацию именно этого CSV: 39 LightGBM + 2 CatBoost, 41 обученная модель.

Отсюда корректное разграничение:
- **Озвученная схема из пяти блоков:** исследовательский вариант архитектуры; это не 5 файлов весов, задействованных при получении `прогноз_5`.
- **v8.1 / `прогноз_5`:** фактическая отправленная модель, 41 вес, официальный проверенный прогноз.
- **v8.2:** + 1 обученная CatBoost количества, итого 42; отдельный эксперимент.
- **v8.3:** 42 неизменённых веса + новая постобработка; отдельные экспериментальные CSV.

Расхождение возникло при сжатом устном представлении нескольких параллельных направлений и относится к **идентификации версии**, а не к переписыванию происхождения отправленного файла. Анализ лидерборда изменил выбор рабочей ветки для дальнейшей разработки; **не следует утверждать, что исходный `прогноз_5` был пересчитан после чекпоинта**.

Для короткого ответа: «На чекпоинте мы представили концепцию одного из исследовательских ансамблей, не уточнив отличие от архитектуры отправленной версии. После сверки leaderboard и сохранённых артефактов зафиксировали фактически использованный вариант: 39 LightGBM и две CatBoost. Именно его развиваем; новые ветки v8.2–v8.3 оформлены отдельно и пока не имеют официальной оценки».
