# ForeStock: инструкция по подключению v8.1 CatBoost

## Для текущей демонстрации

1. Запустить read-only API из этого архива либо импортировать `forecasts/v81_catboost.csv` в PostgreSQL.
2. Отображать на фронтенде девять недель с 27.07.2026 по 21.09.2026 включительно (дата понедельника), разрезы склад/артикул.
3. Исторические продажи/остатки показывать из отдельного хранилища: API готовых прогнозов их не экспортирует.
4. Запуск `app.catboost_inference --verify --recompute-base` позволяет убедиться, что численный результат получен из всех 41 модели.

## Для кнопки «Новый прогноз»

**Текущий API не умеет принимать два CSV.** Не подключать загрузку `sales.csv`/`stock.csv` к `GET /v1/forecasts` и не делать вид, что это пересчитывает прогноз.

Рекомендуемый адаптер:

- `POST /api/jobs/forecasts`: multipart `sales`, `stock`; backend сохраняет файлы, валидирует схему, создаёт `job_id`.
- `GET /api/jobs/forecasts/{job_id}`: статус и ошибка или ссылка на готовый CSV.
- Python worker: `load_and_aggregate(sales, stock)` -> `Dataset` -> `predict_components` -> `v8.enrich` -> обе CatBoost-модели -> `apply_catboost` -> прогноз.
- Для произвольного cutoff обновить функции `base.N_WEEKS`, `base.FINAL`, `snapshot`, рекурсивную логику и календарь; выполнить тесты на нескольких датах и убедиться в отсутствии утечек.
- На уровне worker нельзя использовать фиксированный `training/history_snapshot.npz` вместо загруженных файлов, иначе продукт будет всегда отдавать конкурсный прогноз 2026 года.

## Правила подготовки

- `stock` дублировать нельзя: суммировать по `date+warehouse+article` исходные строки, включая точные дубли.
- `stock=0` не означает обязательный `quantity=0`, остаток на начало дня. Отрицательные остатки допустимы.
- `sales` — настоящие продажи, а не отгрузки. По ключу прогноза суммировать департаменты.
- Обрабатывать полный согласованный набор складов и артикулов, не создавать лишние комбинации.
- 9-недельный горизонт определяется последней полной исторической неделей; для фиксированного конкурса cutoff 26.07.2026.

## Безопасность

Не публиковать OOF, history_snapshot и веса моделей в общедоступный репозиторий. Аутентификация клиент–backend, лимиты загрузки, трейсинг и версии моделей обязательны для реального развёртывания. API в релизе — минимальный read-only пример, не готовая микросервисная инфраструктура.
