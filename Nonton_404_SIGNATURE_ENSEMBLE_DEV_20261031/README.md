# NONTON / команда 404 — сигнатурный ансамбль продаж

**Передача для ML, backend и frontend.** Дата: 31.10.2026.  
**Подтверждённая базовая версия:** v8.1 CatBoost / официальный файл `прогноз_5`.  
**Экспериментальные продолжения:** v8.2 (дополнительная голова количества), v8.3 (постобработка).  
**Статус:** рабочие веса и воспроизводимый прогноз на фиксированную конкурсную сетку. **Это не готовый динамический API для новых CSV.**

## 1. Назначение и ограничения

Прогноз `quantity` на каждую неделю и пару `warehouse_name × article` в течение 9 недель. Начало недель: 27.07.2026, 03.08.2026, ..., 21.09.2026. Результат — `week,warehouse_name,article,quantity`, **79 101 строка** (11 складов × 799 артикулов × 9 недель). Значения вещественные, конечные и неотрицательные. Допустимые данные для обучения и признаков — не позднее **26.07.2026**. Данные после cutoff недопустимы.

`stock` отражает остатки на **начало дня**. Повторные строки для `(date,warehouse_name,article)` суммируются, а не отбрасываются. Нулевой либо отрицательный остаток не является жёстким запретом на продажу. `composite_division` — идентификатор департамента; тождество онлайн/офлайн-каналу не доказано.

## 2. Реальная архитектура отправленного «прогноза №5» — v8.1

**41 обученная модель = 39 LightGBM + 2 CatBoost.**

| Уровень | Алгоритм / назначение | Количество |
|---|---|---:|
| Глобальный | LightGBM Tweedie и Poisson, обучены на общей истории | 2 |
| Склад | Специализированная LightGBM для каждого из 11 складов | 11 |
| Склад × категория первого уровня | 24 специализированные LightGBM для представленных в пакете групп | 24 |
| Рекурсивный | LightGBM Tweedie и Poisson; прогноз по одному горизонту с использованием ранее предсказанных недель | 2 |
| Финальный выбор продажи | CatBoostClassifier, `P(quantity > 0)` | 1 |
| Финальное количество | CatBoostRegressor, цель `log1p(quantity)` | 1 |
| **Итого v8.1** | | **41** |

39 базовых моделей выдают несколько версий прогноза (`v7_global_raw`, `m5lite_raw`, `hybrid_raw`), а не 39 независимых равноправных голосов. В `app/inference.py` базовые варианты собираются из глобального, складского, категорийного и рекурсивного прогнозов; итоговый `hybrid_raw` затем поступает в CatBoost.

Для базовых LightGBM используются **116 признаков** (исторические лаги и частоты продаж, характеристики, уровни и динамика спроса, остатки, ограниченные бакеты департаментов и городов, календарь). Финальные CatBoost используют **62 признака** (сырые прогнозы, их расхождения, историю и динамику по парам/складам/категориям, остатки и календарь). Точный порядок полей строго зафиксирован в `models/base/schema.json` и `docs/model_schema.json`.

Финальная политика v8.1:

```python
p_sale = catboost_prob.predict_proba(X)[:, 1]
amount = max(expm1(catboost_logquantity.predict(X)), 0)
base = max(hybrid_raw, 0)
ratio = clip((amount + 0.25) / (max(base, 0.5) + 0.25), 0.6, 1.8)
quantity = max(base, 0.5) * (1 + 0.5 * (ratio - 1))
prediction = max(quantity, 1.0) if p_sale >= 0.53 else 0.0
```

Формула описывает обработку каждой строки; численное воспроизведение реализовано в `app/catboost_inference.py`. Базовые CatBoost обучались на **7 сохранённых исторических OOF-окнах**, с `iterations=350`, `depth=6`, `learning_rate=0.045`, `l2_leaf_reg=9` и фиксированными seed. Проверка проводится без доступа к скрытым конкурсным ответам.

## 3. Почему именно 41 модель

Количество следует **из состава обученных уровней**, а не из требования использовать «много моделей» или заранее выбранного числа:

- Глобальные модели улавливают общую закономерность и дают опорную оценку; Tweedie и Poisson задают разные предположения о целевой величине.
- 11 складских моделей учитывают неоднородность спроса между складами.
- 24 модели `склад × категория` уточняют поведение конкретных групп, не создавая по модели на каждый из 799 артикулов; все 24 веса присутствуют в архиве.
- Две рекурсивные модели добавляют альтернативный способ расчёта горизонта на несколько недель.
- Две CatBoost выполняют **две разные задачи**: наличие продажи и её количество. Это необходимо при разреженных данных с большим числом нулей.

**41 — зафиксированный размер выбранной и проверенной версии, не доказанный глобальный оптимум.** Добавление моделей без независимого выигрыша по историческим метрикам не считается улучшением.

## 4. Экспериментальная ветка v8.2 / v8.3

**v8.2: 42 обученные модели = исходные 41 + одна CatBoostRegressor**, обученная на положительных фактических продажах (условное количество). Новая голова плавно корректирует величину положительного прогноза; оригинальная вероятность продажи и решение «ноль или продажа» сохранены. Код — `app/v82_inference.py`, веса — `models/experimental/conditional_positive_quantity.cbm`.

**v8.3: те же 42 веса.** Только постобработка для `0 < quantity <= 10`:
- `nearest`: `max(1, floor(quantity + 0.50))`;
- `smape`: `max(1, floor(quantity + 0.65))`;
- нули и значения `> 10` не меняются.

Различия в конкурсных прогнозах:

| Вариант | CSV | Объём за 9 недель | Статус |
|---|---|---:|---|
| v8.1 | `forecasts/v81_catboost.csv` | 222 069 | Отправленный «прогноз №5», официальный Score 0,504 |
| v8.2 | `forecasts/v82_confidence_amount.csv` | 224 762 | Эксперимент, официально не оценён |
| v8.3 nearest | `forecasts/v83_nearest10.csv` | 224 228 | Эксперимент, официально не оценён |
| v8.3 smape | `forecasts/v83_smape10.csv` | 228 244 | Эксперимент, официально не оценён |

**Важно:** локальные исторические оценки v8.3 улучшались, однако окна много раз использовались при отборе гипотез. Это не доказательство улучшения скрытого лидерборда. `RESEARCH_V82_RU.md` и `RESEARCH_V83_RU.md` содержат методы, цифры и ограничения.

## 5. Почему описание на чекпоинте отличается от этого пакета

На чекпоинте рассматривалась **исследовательская концепция из пяти функциональных блоков**: индивидуальный прогноз, независимый нейросетевой прогноз, модель агрегированного спроса, выбор экспертов и коррекция количества. Это описание **не является точной спецификацией отправленного файла `прогноз_5`**.

В ходе последовательных экспериментов сравнивались разные архитектуры. После получения результатов лидерборда команда закрепила **v8.1 CatBoost** как наиболее результативную из первых пяти отправок и продолжила развитие именно её архитектуры (v8.2/v8.3). При коротком устном обсуждении была недостаточно явно разделена пятиблочная исследовательская концепция и фактическая конфигурация, породившая конкурсный CSV.

**Уточнение для разработчиков и защиты:** `прогноз_5` был получен из **39 LightGBM + 2 CatBoost**. Исследовательская схема с пятью блоками существовала как отдельная ветка и не должна приписываться этому CSV задним числом. После лидерборда изменён **приоритет дальнейшей разработки и способ описания решения**, но происхождение уже отправленного прогноза не переписывается. Экспериментальная v8.2 и v8.3 тоже не являются тем самым отправленным прогнозом.

Для внешнего пояснения используйте факты из этого раздела; не утверждайте, что официальная метрика v8.2/v8.3 известна, либо что динамический прогноз по новым файлам уже работает. Отдельная короткая версия для передачи: `docs/CHECKPOINT_NOTE_RU.md`.

## 6. Проверка и запуск на Windows

Требуется Python 3.11+ и PowerShell из **корневой папки архива**.

```powershell
powershell -ExecutionPolicy Bypass -File .\install_windows.ps1
powershell -ExecutionPolicy Bypass -File .\verify_windows.ps1
# Точное воспроизведение исходных 39 LightGBM + 2 CatBoost из весов:
.\.venv\Scripts\python.exe -m app.catboost_inference --verify --recompute-base
# Проверка экспериментального кандидата v8.3:
powershell -ExecutionPolicy Bypass -File .\run_v83_windows.ps1 -Variant nearest -Verify
.\.venv\Scripts\python.exe -m unittest tests.test_v83 -v
```

Без `--recompute-base` используются сохранённые результаты базовых моделей, что быстрее. Для повторного обучения **только дополнительной CatBoost** из уже сохранённых OOF см. `app/v82_retrain_positive.py`; для базовых 39 моделей потребуется отдельная сквозная процедура создания исторических OOF. Не заменять оригинальные веса без последующей проверки.

## 7. Передача в ForeStock: что реализовано

- `app/api.py` — **read-only API только для v8.1**, раздающий ранее рассчитанные прогнозы; маршруты `/healthz`, `/readyz`, `/v1/model`, `/v1/forecasts`, `/v1/export.csv`. Ключ `X-API-Key`, значение из `NONTON_API_KEY`.
- API **не принимает новые `sales.csv` и `stock.csv`**, не пересчитывает forecast и не реализует `POST /predict`. Не заявлять динамический inference.
- Для демо можно импортировать `forecasts/*.csv` в базу и переключать версии **отдельно от текущего API**, либо дорабатывать сервис с явным `version` и инвариантами.
- Для настоящего динамического прогноза нужны ETL новых sales/stock, as-of-окна, сбор всех 116/62 признаков, запуск 39 базовых моделей, две/три головы, модельный контракт и хронологические тесты на нескольких cutoff.

Интеграция описана подробнее в `docs/FORESTOCK_INTEGRATION.md` и `docs/DEV_RUNBOOK_RU.md`.

## 8. Артефакты и безопасность

- `models/base/*.txt` — 39 обученных LightGBM.
- `models/catboost/*.cbm` — 2 оригинальные CatBoost.
- `models/experimental/*.cbm` — дополнительная CatBoost v8.2/v8.3.
- `training/history_snapshot.npz`, `training/final_raw_components.npz`, `training/oof/` — фиксированный historical snapshot, кэш и семь OOF.
- `forecasts/` — эталонные CSV четырёх версий.
- `app/` — inference и историческое переобучение.
- `tests/`, `research/`, `research_v82/`, `research_v83/` — тесты и отчёты.
- `docs/` — схема модели, интеграция, уточнение по чекпоинту и инструкции разработчикам.
- `FILE_SHA256.json` — хеши передаваемых файлов (исключая сам манифест).

**Внутри есть агрегированные коммерческие данные, OOF и модельные веса. Архив только для команды; не выкладывать в открытый репозиторий.**
